The frozen final-test prompt requests `最终答案：C`. Project models often emit
`<answer>最终答案：C</answer>`. The frozen reward parser accepts either a plain
marker or a letter-only answer block, but rejects their combination. The first
complete SFT CMExam job recorded 6,755 unparseable answers out of 6,809. Its v1
accuracy must not be interpreted as medical answer accuracy without this caveat.

The evaluation-only v2 parser unwraps exactly one structurally valid final answer
block and applies the existing explicit-final-marker fallback to its contents.
It preserves ambiguity, legal-option and malformed-control-structure rejection.
It never searches thinking text. A recovered answer counts as fallback, not as
strict training-format compliance. The implementation takes no gold answer as
input. Tests specify both valid marker forms and rejection cases before rescoring.

Training/reward code, selection parser, frozen checkpoint choices, prompts,
decoding, datasets and generation budgets retain their original versions. No
new model inference is requested by this correction. All exam checkpoint outputs
are rescored under v2 from retained raw responses. V1 response files, complete
summaries, receipts and original seals are retained unchanged. This is an explicit
post-observation correction, not a claim that v2 was frozen before the test run.

`scripts/rescore_stage5_exams_v2.py --watch` follows completed exam generation jobs
on CPU. Corrected predictions and provenance live under
`stage5_project_v1/rescored_v2`; compact results/status live under
`experiments/stage5/parser_correction_v2`. It verifies raw/receipt hashes, adapter
identity and the original v1 scores before deriving v2 scores. The original
objective verifier separately retains full token, prompt and attempt replay.

The existing generator and its frozen v1 audit continue for evidence retention.
Any `*_results_v1.json`, v1 case mining, or legacy handoff generated by that process
uses the old parser and is superseded for exam-accuracy interpretation by the
v2 outputs. Final Stage5 reporting must reference the v2 tables, preserve the v1
comparison and disclose this correction; the legacy objective PASS alone does
not certify the v2 scores. Open QA, clinical review and Stage6 remain separate.

New scoring uses the same checkpoints for selected-model and equal-update
comparisons, keeps their tables separate, and retains the frozen slices and
paired-statistics seed/resampling budget. No checkpoint is selected again.

Resource impact: zero new GPU generation or paid API calls; CPU rescoring and
additional immutable predictions/provenance. Follow-up: finish all eight unique
exam jobs, inspect corrected parsing rates, and integrate v2 cases and results
into the final report/handoff before claiming objective evaluation complete.
